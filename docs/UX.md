# UX — PromptNote / 提词笺

本文件定义 V1 的用户体验主链和交互原则。实现不得为了技术方便破坏这些体验边界。

## 1. 核心体验主链

```text
打开 PromptNote Side Panel
        ↓
直接自然书写
        ↓
可选使用 / 插入结构块
        ↓
可选使用 AI 建议 / 内联补全 / Prompt lint
        ↓
预览编译结果
        ↓
复制到目标 AI 工具
```

PromptNote V1 不再向第三方网页输入框写入内容。Copy 是稳定、站点无关的外部输出动作。

## 2. 编辑器体验

### 2.1 默认就是普通文档

用户打开编辑器后可以直接输入文本，不要求先选择模板、角色或 Prompt 类型。

默认编辑体验接近 Notion / 飞书文档：

- 输入即编辑；
- 支持标题、段落、列表、代码块、引用；
- 支持撤销/重做；
- 选中文字后在 Side Panel 底部主操作栏上方出现稳定、紧凑的选区操作条；
- 不显示 Markdown 符号作为主要编辑体验。

选区操作不得依赖文字旁边的微型 `•••`、浏览器 DOM selection 的临时坐标或必须先点一次才能展开的二级入口。窄 Side Panel 中“能稳定出现、能直接点击”优先于追求贴着文字的浮动效果。

TipTap/ProseMirror `PromptEditor` 在 V1 中保持同步打包。2026-08-08 的真实 Chrome 验证证明，对 Editor 运行时使用 `React.lazy + dynamic import()` 会造成 Side Panel 短暂显示后白屏，因此该拆分已撤销。AI 设置与本地 Prompt 管理 Sheet 仍可按用户打开时异步加载，但任何 lazy boundary 都不得复制 PromptDocument、设置或保存状态。

### 2.2 Slash Menu

`/` 是上下文 Slash Command，而不是全局拦截字符：

- caret 为空选区，且位于文本块/行首，或前一个字符为空白时输入 `/` → 打开结构菜单；
- URL、日期、路径、`A/B` 等正文中的 `/` → 作为普通字符输入，不打开菜单；
- 菜单支持 `↑` / `↓`、`Home` / `End`、`Enter`；
- 菜单打开后按 `Esc` → 关闭菜单并把该 `/` 作为普通字符写回原 caret。

V1 Prompt 语义块：

- `/目标` Goal
- `/背景` Context
- `/任务` Instruction
- `/约束` Constraint
- `/示例` Example
- `/输出格式` Output Format
- `/验收标准` Acceptance

普通文档块仍可存在，例如标题、列表、代码、引用，但不得和 Prompt 语义块重复实现两套内容模型。

### 2.3 结构块不是固定表单

用户可以：

- 自由文本与结构块混写；
- 把现有段落转换成结构块；
- 删除结构标签而保留文字；
- 任意调整顺序。

不得要求所有 Prompt 必须包含固定字段。

语义块必须在**常态**下就有明确视觉边界：可见边框、左侧强调线、语义标签和足够块间距。hover / focus 只允许做增强，不能依赖 hover 才看得出模块分界；同时不得做成重型表单/卡片墙。

## 3. AI 辅助体验

### 3.1 AI 总开关与补全开关分离

AI 设置必须区分：

1. `启用 AI 辅助`：允许显式 AI 动作；
2. `编辑器内联补全`：允许编辑停顿时自动请求短续写。

内联补全默认关闭。只有同时满足以下三个条件才允许自动请求 Provider：

```text
AI 已配置成功
AND AI 辅助已启用
AND 编辑器内联补全已开启
```

关闭 AI 总开关时，补全必须同时失效；用户没有打开补全开关时，不得因为 AI 已连接就在后台自动补全。

### 3.2 IDE 风格内联补全

当补全开启后：

- 用户继续自然书写，也可以把 caret 放到**之前已经存在的文本**中请求补全；“这段文字是否刚刚输入”不能改变能力是否可用；
- 对已有长文本块，聚焦、移动 caret、重新打开文档时的补全热路径必须只处理 `completionContextChars` 附近的局部内容；不得为了最后发送 320 字，先把几千/几万字整个 block 转成字符串；
- 光标停顿短时间后，可在当前 caret 后显示低对比度灰色 ghost text；
- **中文、日文等 IME 仍处于 composition/组词阶段时不得发补全请求**；只有输入法提交出稳定正文后，才允许基于真实 caret 建立补全 context；
- **补全只针对当前正在编辑的文本块**；当前块是“背景”时，不得把前一个“输出格式/任务/约束”等块的正文偷偷拼进补全上下文；
- 语义块类型可以作为辅助提示发送给模型，例如“当前模块：背景”，但模块标签不能被重复输出进正文；
- Provider 支持 streaming 时，第一批有效文本一到就应尽快开始显示，不等待整段续写完成；
- streaming partial 可以在很短时间窗口内合并刷新，避免每个 token 都触发整页 React render，但不得因此重新退化成“整段生成完才显示”；
- 对兼容网关的响应以**实际 body 形态**为准，不能只相信 `Content-Type`；例如 header 错写成 `text/event-stream`、body 实际是普通 JSON 时仍应正确降级，而不是报“流式补全返回空内容”；
- 流式返回过程中 `Tab` 可以接受当前已经出现的 partial，接受后旧请求立即失效；
- ghost 必须绑定请求发起时的 document/block/caret 和用户当前配置的 context budget；用户移动光标、切换块、切换文档、继续输入、调整补全上下文、进入 IME composition 或编辑器失焦后，旧 partial/ghost 不得重新出现在新的 caret；
- ghost text 不属于 PromptDocument，不参与自动保存、Compiler 或 revision；
- `Tab` 只接受当前 caret 仍与 ghost 原始位置一致的补全；位置已变化时必须拒绝旧 ghost；
- `Esc` 忽略补全，不修改正文；
- 用户继续输入、移动光标或正文变化后，旧补全立即失效；
- **编辑停顿防抖与真实 Provider 请求频率必须分开治理**：即使用户在较长中文句子中多次自然停顿，也不能把每个停顿都变成一次新的网络请求；这是一条通用稳定性约束，不等同于“已有长文本失败”的根因；
- 补全请求必须取消已经过期的请求，不允许并发堆积；
- 短时 429、5xx、超时或网络抖动属于可恢复错误，应在当前 caret/context 仍有效时有限次自动退避重试，并尊重 Provider 的 `Retry-After`；
- 认证失败、配置错误、额度/配额耗尽等持久错误必须尽快向用户显示真实原因，不得无限静默重试；持久错误也不得给下一处全新的 caret/context 强加额外 30 秒等待；
- 单次短时错误不得立即弹出“AI 补全不可用”干扰正常写作；只有连续自动恢复失败后才升级为用户可见状态；
- 用户可见的补全失败提示应包含经过长度限制的真实 Provider 原因，而不是永远只显示“请检查连接”；后续补全成功后必须清掉已经失效的 AI error 状态；
- 退避窗口内用户形成了新的有效输入时，旧 context 的等待/重试立即失效，由新 context 接管；
- 已成功生成过的相同 context 再次命中本地短缓存时，应直接恢复 ghost，不先清空再重新构造 Provider 请求；
- 如果流已经返回可用 partial 后才发生网络中断，优先保留已经出现且仍属于当前 caret 的 partial，而不是把可用建议清掉。

补全应短、局部、延续当前意图，不允许自动生成整篇 Prompt。

### 3.3 其他 AI 动作仍必须显式触发

内联补全之外，AI 不得因为用户输入或选中文字就自动修改内容。

用户选中文字后，底部主操作栏上方直接出现选区操作条：

- `改清楚`；
- `缩短`；
- `拆约束`；
- `更多 AI`；
- 当前文本块类型转换。

选区操作状态只以编辑器自身的 ProseMirror selection 为准，不再读取 `window.getSelection()` 或维护 viewport rect。若选区跨多个文本块，AI 文本动作仍可执行，但“文本类型”转换必须禁用并明确显示跨块状态。

不得同时悬浮两套独立工具条，不得重新加入文字旁的 `•••` 二级入口。

全局 AI 入口用于：

- 检查当前 Prompt 的歧义；
- 生成验收条件；
- 给出结构整理建议；
- AI 深度 Prompt lint。

这些结果必须先作为 suggestion/advisory 展示；只有用户接受后才能修改 PromptDocument。正文变化后，过期 suggestion 必须禁止应用。

### 3.4 AI 设置入口

Top Bar 提供轻量状态入口：

- `AI 未配置`；
- `AI 已连接`；
- `AI · 补全开`；
- `AI 已关闭`。

AI 设置至少包含：

- AI 总开关；
- 编辑器内联补全独立开关；
- Provider；
- Model；
- API Base URL；
- API Key；
- 默认发送范围；
- 测试连接；
- 保存配置。

高级设置可折叠提供：

- **补全模型（可选）**：留空沿用主 Model；填写后只有内联补全使用该模型，适合选择更低延迟的模型；
- 补全上下文快捷预设：`短 160 / 中 320 / 长 640 / 自定义`，默认 320；
- 补全触发延迟快捷预设：`快 150ms / 平衡 300ms / 稳 600ms / 自定义`，默认 300ms；
- 自定义上下文允许 16–2000 字符；
- 自定义触发延迟允许 50–3000ms；
- 每个 AI 动作的指令模板覆盖；留空即恢复该动作的内置默认。

预设只用于快速选择，持久化的是最终数值本身，不保存第二套 preset/customValue 状态。修改补全性能参数、补全模型或 AI 指令模板不应使已验证的主 Provider 连接失效；只有 Provider、主 Model、Base URL、API Key 等连接身份发生变化时才需要重新验证。

PromptNote 保留一层公共 AI 行为约束；用户自定义的是单个功能的任务指令，不自动移除公共约束。

Provider、模型、credential、补全偏好、补全性能参数、补全模型与 AI 指令覆盖都属于 Extension Preferences，不属于 PromptDocument。

### 3.5 内容发送范围必须可理解

默认选区 AI 动作只发送用户主动选中的文字；可选“选区 + 当前 Prompt 上下文”。

全局动作若需要完整 Prompt，入口必须明确表达。

内联补全只发送**当前 text block 内**、以 caret 为中心且受用户设置限制的有限文本；`completionContextChars` 是当前块的最大上下文预算，不代表跨多个语义块向前取 N 个字符。不能借补全能力静默扩大为全文长期上传。

### 3.6 无 AI 也能完整使用

未配置 AI、API 失败、用户禁用 AI 或关闭补全时，以下能力必须继续工作：

- 编辑；
- 结构化；
- 保存；
- 本地 Prompt lint；
- Compiler；
- Copy。

AI 配置失败不得被表现为整个 PromptNote 不可用。

## 4. Prompt lint

Prompt lint 的目标是提示潜在问题，不是给 Prompt 打分。

V1 本地规则可检测：

- 模糊词；
- 未定义引用；
- 目标与验收条件缺失；
- 明显重复段落；
- 过长但无结构的内容。

需要语义判断的增强检查由用户显式触发 AI。Lint 默认只提示，不阻止复制。

检查结果属于 transient panel，必须固定在底部主操作栏上方并拥有自己的滚动区域；不得继续作为正文末尾内容被主操作栏挡住。

## 5. 编译、预览与复制

用户始终编辑 PromptDocument；Preview 只显示 Compiler 派生结果。

V1 输出：

- Plain Text；
- Markdown；
- XML。

切换输出格式不得修改 PromptDocument。

编辑页底部 `复制` 默认复制 Plain Text，避免用户曾在 Preview 里选择 Markdown/XML 后，回编辑页产生不可见格式状态。

Preview 中可以选择格式并复制当前格式；不允许编辑 Preview 形成第二内容源。

## 6. Side Panel 布局原则

V1 优先单栏、低干扰布局：

```text
┌──────────────────────────────────┐
│ Prompt 标题          [AI 状态]   │
├──────────────────────────────────┤
│                                  │
│            编辑区域              │
│      灰色 ghost completion       │
│                                  │
├──────────────────────────────────┤
│ [按需：选区/检查/AI 临时面板]    │
├──────────────────────────────────┤
│      检查       预览       复制  │
└──────────────────────────────────┘
```

底部 transient surface 必须遵循单一视觉优先级：

```text
AI 生成中 > AI suggestion > 检查结果 > 选区操作条
```

低优先级状态可以保留，但当更高优先级面板显示时不得同时占据相同视觉空间、互相遮挡。

不在底部保留“插入网页”占位按钮。AI 状态入口必须可发现，但视觉权重低于正文。

AI 设置和本地 Prompt 管理不是首屏编辑所需能力，可以按用户打开时再加载；lazy-load 不得改变其状态语义或制造第二套设置状态。

不在 V1 默认页面加入大型 Dashboard、复杂导航树、数据统计或常驻 AI Chat。

## 7. 保存与恢复

编辑内容自动保存到唯一 PromptDocument。

用户关闭 Side Panel、刷新页面、重启浏览器后应能恢复最近编辑内容。保存失败必须可见，不能假装成功。

同一 Prompt 的 revision 必须单调；更旧 revision 的异步保存不得覆盖已经持久化的更新 revision。顶部“已保存”只允许表示**当前编辑中的最新 document id + revision**已经成功持久化；旧 revision 的晚到成功回调不得把仍在编辑的新 revision 错标为“已保存”，也不得把文档列表回退到旧快照。

从电脑恢复备份时，如果备份与本地文档同 ID，用户明确选择“覆盖”必须产生一个高于本地与备份双方的更新 revision，再写入 Repository；不能被旧 revision 防回退规则静默拒绝。即使 document id 没变，覆盖后的外部内容也必须立即替换当前 Editor；普通本地键入则不得因此触发整份 Editor `setContent()` 重灌。

如果用户拒绝同 ID 覆盖，导入副本必须使用新 id，并保持与原文档相互独立。

ghost completion、AI suggestion、lint findings、Preview 都是派生/临时状态，不得成为持久正文源。

## 8. 可用性底线

- 核心操作必须支持键盘；
- Side Panel 在浏览器实际允许的窄宽度下仍可使用；V1 Chrome 真机已验证约 382px；
- 不依赖 hover 才能发现关键能力；
- 错误信息描述真实失败原因，不使用假成功；
- 用户内容删除需要明确动作；
- `Tab` 只在仍属于当前 caret 的 ghost completion 可见时接受补全；
- `Esc` 优先忽略 ghost completion，否则关闭当前最上层临时 UI；
- 不因为 Lint、AI 未配置、补全失败或 suggestion 阻断用户继续编辑；
- 选中文字后必须有稳定、可直接点击的操作入口，不能依赖文字旁临时坐标按钮。

## 9. UX 变更规则

如果新功能要求用户多经过一个强制步骤才能完成当前主链，必须证明其必要性。

优先增加可选增强，不增加强制流程。
