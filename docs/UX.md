# UX — PromptNote / 提词笺

本文件定义 V1 的用户体验主链和交互原则。实现不得为了技术方便破坏这些体验边界。

## 1. 核心体验主链

```text
打开 ChatGPT / Claude / Gemini
        ↓
打开 PromptNote Side Panel
        ↓
直接自然书写
        ↓
可选使用 / 插入结构块
        ↓
可选使用 AI 建议 / Prompt lint
        ↓
预览编译结果
        ↓
复制 或 插入当前网页
```

V1 的所有核心能力都应围绕这条主链工作。

## 2. 编辑器体验

### 2.1 默认就是普通文档

用户打开编辑器后可以直接输入文本，不要求先选择模板、角色或 Prompt 类型。

默认编辑体验接近 Notion / 飞书文档：

- 输入即编辑；
- 支持标题、段落、列表、代码块、引用；
- 支持撤销/重做；
- 支持选中文本后的轻量浮动操作；
- 不显示 Markdown 符号作为主要编辑体验。

### 2.2 Slash Menu

输入 `/` 后提供结构块与常用文档块。

V1 Prompt 语义块：

- `/目标` Goal
- `/背景` Context
- `/任务` Instruction
- `/约束` Constraint
- `/示例` Example
- `/输出格式` Output Format
- `/验收标准` Acceptance

普通文档块仍可存在，例如标题、列表、代码、引用，但不得和 Prompt 语义块重复实现两套内容模型。

### 2.3 结构块不是固定表单

用户可以：

- 自由文本与结构块混写；
- 把现有段落转换成结构块；
- 删除结构标签而保留文字；
- 任意调整顺序。

不得要求所有 Prompt 必须包含固定字段。

## 3. AI 辅助体验

### 3.1 默认不主动改文

AI 不得在用户输入时自动替换内容，也不得在后台悄悄“优化”。

### 3.2 AI 通过显式动作触发

V1 可提供：

- 改清楚；
- 缩短；
- 检查歧义；
- 拆成约束；
- 生成验收条件；
- Prompt lint。

### 3.3 建议先于修改

AI 结果必须明确区分原文和建议：

```text
原文
────────
不要乱改其他地方

建议
────────
仅修改与本问题直接相关的代码；不得扩大修改范围。

[接受] [忽略]
```

允许后续增加局部选择接受，但 V1 不要求复杂 Track Changes 系统。

### 3.4 无 AI 也能完整使用

未配置 AI、API 失败或用户禁用 AI 时：

- 编辑；
- 结构化；
- 保存；
- Compiler；
- Copy；
- Web Insert

必须继续工作。

## 4. Prompt lint

Prompt lint 的目标是提示潜在问题，不是给 Prompt 打“高低分”。

V1 可检测：

- 模糊词：如“尽量”“适当”“处理一下”；
- 未定义引用：如“这个文件”“上面的逻辑”但无上下文；
- 目标与验收条件缺失；
- 互相冲突的约束；
- 明显重复段落；
- 过长但无结构的内容。

Lint 默认只提示，不阻止复制或插入。

## 5. 编译与预览

用户始终编辑 PromptDocument；预览区域显示 Compiler 结果。

V1 输出：

- Plain Text；
- Markdown；
- XML。

切换输出格式不得修改 PromptDocument。

用户可以：

- 复制当前格式；
- 插入当前格式；
- 查看编译预览。

不允许“编辑 Markdown 预览”形成第二内容源。

## 6. Side Panel 布局原则

V1 优先单栏、低干扰布局：

```text
┌──────────────────────────────┐
│ Prompt 标题            ⋯     │
├──────────────────────────────┤
│                              │
│          编辑区域            │
│                              │
│  / 插入结构块                │
│                              │
├──────────────────────────────┤
│ Lint   Preview   Copy/Insert │
└──────────────────────────────┘
```

不在 V1 默认页面加入大型 Dashboard、复杂导航树或数据统计。

如果需要打开其他 Prompt，使用轻量文档列表/搜索入口即可，不扩展成 Prompt 管理后台。

## 7. 网页插入体验

Web Adapter 负责识别目标网页输入框并插入 Compiler 输出。

插入必须满足：

- 用户明确点击触发；
- 不自动发送消息；
- 不覆盖输入框已有内容而不提示；
- Adapter 失败时可退化为 Copy；
- 网站 DOM 变化不能破坏编辑器本身。

V1 至少完成一个真实站点的端到端 Adapter，再扩展其他站点。

## 8. 保存与恢复

编辑内容应自动本地保存，但自动保存只写唯一 PromptDocument。

用户关闭 Side Panel、刷新页面、重启浏览器后应能恢复最近编辑内容。

保存失败必须可见，不能假装成功。

## 9. 可用性底线

- 核心操作必须支持键盘；
- Side Panel 窄宽度下仍可使用；
- 不依赖 hover 才能发现关键能力；
- 错误信息描述真实失败原因，不使用假成功；
- 用户内容删除需要明确动作；
- 不因为 Lint 或 AI 建议阻断用户继续编辑。

## 10. UX 变更规则

如果新功能要求用户多经过一个强制步骤才能完成当前主链，必须证明其必要性。

优先增加可选增强，不增加强制流程。
