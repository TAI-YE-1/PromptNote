# UX — PromptNote / 提词笺

本文件定义 V1 的用户体验主链和交互原则。实现不得为了技术方便破坏这些体验边界。

## 1. 核心体验主链

```text
打开 ChatGPT / Claude / Gemini
        ↓
打开 PromptNote Side Panel
        ↓
直接自然书写
        ↓
可选使用 / 插入结构块
        ↓
可选使用 AI 建议 / Prompt lint
        ↓
预览编译结果
        ↓
复制 或 插入当前网页
```

V1 的所有核心能力都应围绕这条主链工作。

## 2. 编辑器体验

### 2.1 默认就是普通文档

用户打开编辑器后可以直接输入文本，不要求先选择模板、角色或 Prompt 类型。

默认编辑体验接近 Notion / 飞书文档：

- 输入即编辑；
- 支持标题、段落、列表、代码块、引用；
- 支持撤销/重做；
- 支持选中文本后的轻量浮动操作；
- 不显示 Markdown 符号作为主要编辑体验。

### 2.2 Slash Menu

输入 `/` 后提供结构块与常用文档块。

V1 Prompt 语义块：

- `/目标` Goal
- `/背景` Context
- `/任务` Instruction
- `/约束` Constraint
- `/示例` Example
- `/输出格式` Output Format
- `/验收标准` Acceptance

普通文档块仍可存在，例如标题、列表、代码、引用，但不得和 Prompt 语义块重复实现两套内容模型。

### 2.3 结构块不是固定表单

用户可以：

- 自由文本与结构块混写；
- 把现有段落转换成结构块；
- 删除结构标签而保留文字；
- 任意调整顺序。

不得要求所有 Prompt 必须包含固定字段。

## 3. AI 辅助体验

### 3.1 默认不主动改文

AI 不得在用户输入时自动替换内容，也不得在后台悄悄“优化”。

### 3.2 AI 必须通过显式动作触发

用户选中文字后，只显示轻量浮动工具条；**不得因为选中了文字就直接调用 AI 或直接生成建议**。

选区动作可包括：

- 改清楚；
- 缩短；
- 拆成约束；
- 更多 AI 动作。

在 Side Panel 的窄编辑区域中，选区默认只显示**一个紧凑的上下文入口**。点击后才展开 AI 辅助动作和当前文本块类型转换；不得同时悬浮两套独立工具条或常驻展开全部动作遮挡正文。

全局 AI 入口用于当前 Prompt 级动作，例如：

- 检查当前 Prompt 的歧义；
- 生成验收条件；
- 给出结构整理建议；
- AI 深度 Prompt lint。

本地 deterministic lint 和 AI lint 必须区分：基础检查不依赖 AI；只有需要语义判断的增强检查才调用 AI。

### 3.3 AI 配置入口

Top Bar 提供一个轻量 AI 状态入口，至少有三种状态：

- `AI 未配置`；
- `AI 已连接`；
- `AI 已关闭`。

点击后：

- 未配置 → 打开 AI 辅助设置；
- 已配置 → 打开 AI 辅助动作面板，并可进入设置；
- 已关闭 → 显示关闭状态并允许重新启用。

AI 设置不得常驻占用编辑器主要空间，也不得演变成模型 Playground。

V1 AI 配置至少表达以下概念：

- 是否启用 AI 辅助；
- Provider；
- Model；
- API Base URL（可选，用于兼容端点）；
- API Key；
- 默认发送范围；
- 测试连接；
- 保存配置。

Provider 和模型选择属于 AI assistance 配置，不得修改 PromptDocument，也不得为不同模型维护 Prompt 正文副本。

### 3.4 内容发送范围必须可理解

默认选区 AI 动作只发送用户主动选中的文字。

可提供：

- 仅选中文字（默认）；
- 选区 + 相邻上下文。

如果某项动作必须读取完整 Prompt，例如“检查当前 Prompt 的歧义”，触发入口必须明确提示该动作会使用当前 Prompt，而不能借用户配置“仅选区”后静默扩大数据范围。

### 3.5 建议先于修改

AI 结果必须明确区分原文和建议：

```text
原文
────────
不要乱改其他地方

建议
────────
仅修改与本问题直接相关的代码；不得扩大修改范围。

[接受] [忽略]
```

只有用户点击接受，Editor command 才能修改 PromptDocument。

如果正文在 suggestion 生成后已经变化，过期 suggestion 必须被标记并禁止直接应用。

允许后续增加局部选择接受，但 V1 不要求复杂 Track Changes 系统。

### 3.6 无 AI 也能完整使用

未配置 AI、API 失败或用户禁用 AI 时：

- 编辑；
- 结构化；
- 保存；
- 本地 Prompt lint；
- Compiler；
- Copy；
- Web Insert

必须继续工作。

AI 配置失败不得被表现为整个 PromptNote 不可用。

## 4. Prompt lint

Prompt lint 的目标是提示潜在问题，不是给 Prompt 打“高低分”。

V1 本地规则可检测：

- 模糊词：如“尽量”“适当”“处理一下”；
- 未定义引用：如“这个文件”“上面的逻辑”但无上下文；
- 目标与验收条件缺失；
- 明显重复段落；
- 过长但无结构的内容。

需要语义判断的能力，例如更复杂的约束冲突、歧义和意图完整性，可由用户显式触发 AI 深度检查。

Lint 默认只提示，不阻止复制或插入。

## 5. 编译与预览

用户始终编辑 PromptDocument；预览区域显示 Compiler 结果。

V1 输出：

- Plain Text；
- Markdown；
- XML。

切换输出格式不得修改 PromptDocument。

用户可以：

- 复制当前格式；
- 插入当前格式；
- 查看编译预览。

不允许“编辑 Markdown 预览”形成第二内容源。

## 6. Side Panel 布局原则

V1 优先单栏、低干扰布局：

```text
┌──────────────────────────────────┐
│ Prompt 标题          [AI 状态]   │
├──────────────────────────────────┤
│                                  │
│            编辑区域              │
│                                  │
│    / 插入结构块                  │
│                                  │
├──────────────────────────────────┤
│ 检查      预览      复制   插入  │
└──────────────────────────────────┘
```

AI 状态入口必须可发现，但视觉权重低于正文和 Insert 主操作。

不在 V1 默认页面加入大型 Dashboard、复杂导航树、数据统计或常驻 AI Chat。

如果需要打开其他 Prompt，使用轻量文档列表/搜索入口即可，不扩展成 Prompt 管理后台。

## 7. 网页插入体验

网页插入默认遵循用户已经熟悉的“粘贴到当前编辑位置”语义，而不是让用户先选择“追加整框 / 替换整框”。

默认规则：

- 当前输入框存在选区 → 只替换当前选区；
- 当前输入框存在折叠光标 → 插入到当前光标；
- 输入框为空 → 直接插入；
- 能识别输入框但无法恢复可靠光标 → 退化到该输入框末尾，并明确提示；
- 无法确定目标输入框 → 要求用户先点击目标输入框，不猜测多个候选；
- 永不自动发送/提交。

通用网页输入能力优先覆盖标准 `input / textarea / contenteditable`。ChatGPT、Claude、Gemini 等站点 Adapter 只用于特殊 DOM / 富编辑器兼容，不得成为“能否插入”的唯一入口。

为降低网页常驻开销和站点访问范围，PromptNote 不向所有网页永久注入 content script。用户点击扩展图标时，只对当前标签页使用临时 `activeTab` 权限预热轻量网页 bridge；Bridge 丢失时可在明确用户操作下重新注入。

Adapter / bridge 失败时必须：

- 明确显示真实失败；
- 允许 Copy 降级；
- 不破坏 PromptDocument、Editor 或 Storage；
- 不把底层 Chrome 消息错误原样暴露给用户。

V1 至少验证一个真实 AI 网页端到端可用；通用输入框行为使用 DOM fixture 覆盖，特殊站点只在确有差异时增加 Adapter。

## 8. 保存与恢复

编辑内容应自动本地保存，但自动保存只写唯一 PromptDocument。

用户关闭 Side Panel、刷新页面、重启浏览器后应能恢复最近编辑内容。

保存失败必须可见，不能假装成功。

AI Provider、Model、Base URL、API Key、启停状态和发送范围属于扩展设置，不属于 PromptDocument 正文状态。

## 9. 可用性底线

- 核心操作必须支持键盘；
- Side Panel 窄宽度下仍可使用；
- 不依赖 hover 才能发现关键能力；
- 错误信息描述真实失败原因，不使用假成功；
- 用户内容删除需要明确动作；
- 不因为 Lint、AI 未配置或 AI suggestion 阻断用户继续编辑。

## 10. UX 变更规则

如果新功能要求用户多经过一个强制步骤才能完成当前主链，必须证明其必要性。

优先增加可选增强，不增加强制流程。
